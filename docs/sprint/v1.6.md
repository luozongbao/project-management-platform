**v1.6.0** release. **No new features**, **no schema changes**, **no

## Risk register

| Risk | Mitigation |
|---|---|
| Per-page CSS strip may break a visual that depends on a per-page override | The audit step is the acceptance test (visual diff before/after, and `task_layout_issue013_test.php` source-grep test still passes). Any divergence from the global rule is tagged `/* per-page override of .X in style.css */` so a future dev knows the duplication is intentional. |
| A fresh deploy with the `02-subtask.sql` mount removed may fail on a database that already has those triggers from a pre-v1.6 install | The live DB has zero triggers today, so this is a non-issue for the current install. For a hypothetical upgrader, the migration is `DROP TRIGGER IF EXISTS …` run once, then drop the file. Document this in the upgrade notes (RELEASE.md). |
| `register_shutdown_function` cleanup may itself fail (e.g. on a fatal E_COMPILE_ERROR) | The shutdown handler is wrapped in an `is_file()` check, so a file that was already deleted is a no-op. Worst case: the file is left behind; the next test run uses a fresh random name. |
| In-process `include` of a page that calls `requireLogin()` will `exit()` before any HTML is emitted | The two existing patterns are: (a) stub the helper via `auto_prepend_file`, or (b) skip the live render and rely on source-grep. v1.5.1 established (b) as the right level of coverage for CSS-class fixes; do not regress to (a) without a strong reason. |
| New `database/README.md` and `client/README.md` describe a pattern that drifts over time | Both READMEs link to `issue-014.md` and `task_layout_issue013_test.php` as the canonical example. Future PRs that change the pattern are expected to update the README in the same PR. |

## Out of scope (flagged for future tickets)

- Move `APP_URL` and the SMTP constants out of `config.php` and into `.env` so `docker/entrypoint.sh` is the only path to a working `config.php`. (v2.0.)
- Switch the four procedural pages to a templating engine or framework. (v2.0.)
- Add an Nginx-level health check endpoint and wire it to the `web` container's `healthcheck`. (Cosmetic.)
- Translate the internal app to a second language. The current design (EN-only internal, EN+ZH client) is the spec; do not break it.
- Move the page-unique sub-task tree styling from `task_detail.php` into `style.css` and replace the markup with semantic classes. (Markup changes are out of scope for v1.6.0; this would let the per-page CSS line count drop below the spec's 250-line target.)
